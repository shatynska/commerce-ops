{# The header every admin surface carries, naming both surfaces the session can reach. Included from `launch`'s templates and from `access`'s alike, through a `ChoiceLoader` over this directory — one copy, so the two surfaces cannot drift apart the way the roster page's inline styles did. `current` says which surface is being viewed: `"playbook"` from the step list and from both authoring surfaces (an admin authoring a step is within the playbook surface), `"roster"` from the roster page. The current one is identified rather than linked, so the header reads as a position rather than as an undifferentiated pair of links. The paths are literals. `launch` cannot import `access`'s `PAGE_PATH`, and `access` already writes `launch`'s path as a literal (`ADMIN_HOME_PATH`), so one literal pair in one shared partial is strictly fewer than the two in two modules that stood here before. The outbound link from the playbook surfaces is un-boosted, for the reason `page.html`'s Add step control already records: `hx-boost` is inherited from ``, so htmx would swap the roster page into this page's body, discard that page's own body attributes and leave a roster page that cannot post. #}

{# Where a failed write is reported, and the behaviour that reports it — shipped together, in the one partial every admin surface includes. Together, deliberately. A listener that reaches for a slot each page happens to own is a listener that finds nothing and fails silently on the page that lacks one, which is the very defect this exists to fix. Pairing them here makes "the handler has somewhere to render" true by construction rather than by inspection of two templates. `write-failure-notice` names the container's ROLE, so it sits on every admin page whether or not anything has failed. `write-failed` is added only when a failure has actually been reported into it — the same discipline `just-created` follows, where a marker asserting an occurrence must never outrun the occurrence. #}
