It was wrong in four ways at once, and all four are the reasons `restore-admin-step-writes` exists: - it claimed "nothing was saved", which a listener watching a response status cannot establish -- a failure raised after the write landed answers identically to one raised before it; - it lived here, so the edit surface -- boosted exactly the same way -- had no failure handling whatsoever; - it bound `htmx:responseError` alone, leaving a submission that gets no response (a deploy restart) as silent as before; - it acted only on 404, so the 500 every broken write actually answered fell straight through it, which is why a whole page of dead writes looked like a page where clicking Save simply did nothing; - and it replaced the document body to display a sentence, destroying the page to report on it. #}
