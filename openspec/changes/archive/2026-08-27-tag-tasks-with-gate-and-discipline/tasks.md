## 3. Verification

- [x] 3.0 **Process record.** The two `AGENTS.md` gates were skipped on the first pass at the user's direction; both were run late rather than waived. `openspec-change-reviewer` ran eight times over 2026-08-26. Rounds one and two found the substantive design faults: an exclusion rule naming two of three departure fields, an unsatisfiable create-path failure clause, and — the largest — that failing the pass on a vocabulary fault would let a tag-API fault stop projection and completion intake for every launch, contradicting the rule that tagging never runs ahead of the projection. Rounds three to six were spent almost entirely on the failure model of the seeding subsystem, each round's fixes introducing the next round's defects. Round six flagged as unsupported the assumption a create could be rejected for a tag in its body; probing that overturned the premise the whole change rested on (see 3.7), and the subsystem was deleted. Round seven found only editorial residue; round eight returned PROCEED WITH CHANGES with minors only. One finding was **rejected with evidence** and the rejection upheld on re-examination: the reviewer asked for the capability `Purpose` change to travel in the delta, citing `add-clickup-completion-loop`; that change *created* the capability, the one case where a delta carries a `Purpose`, and all four later changes to this existing capability carry none. The reviewer's own second look found nine archived changes declaring the direct edit as a task.
- [x] 3.0a **Lesson worth keeping: a green suite proved nothing about a deletion.** A scripted removal of the seeding code reported success but did not persist, and the full suite stayed green across two verification runs — because the tests for that code had already been deleted and the job no longer imported it, so nothing referenced the dead code that remained. It was found by grep, not by tests. Where work is *removal*, verify by searching for the symbols, not by running the suite.
