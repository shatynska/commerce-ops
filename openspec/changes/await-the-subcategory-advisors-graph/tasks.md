## 2. The tests move first, and the source does not move until they have

The order is not a preference. `design.md`'s Risks section names the failure this ordering makes unreachable: convert the source first and the commit-time tier fails with *"the advisor never called `with_structured_output(...)`"* — a message accusing the advisor of the test's own omission, from `tests/unit/step_handlers/listing/test_subcategory_advisor_schema_conversion.py`. An implementer who sees that message has done section 3 before section 2.

Tests written in this section fail until section 3 lands. That is expected and is the point; **do not** weaken an assertion to make one pass early.

**Sections 2 and 3 are one commit.** `AGENTS.md` asks for a commit at each meaningful milestone, and this section is not one: the pre-commit hook runs the entire `tests/unit`+`tests/agents` tree, so a commit here is blocked by the very tests this section deliberately leaves red. An implementer who tries to commit between the two sections and reaches for an assertion to clear the hook has been pushed into exactly what 2.2 forbids. Do not split them.

- [x] 2.1 Take the test files from `ai-toolkit:openspec-test-writer`, not from this list. This section says what must be true of the migration, not what the tests are. **Dispatch the writer with `design.md` Decisions 2 and 5 and tasks 2.2–2.7 as named inputs alongside the delta.** `AGENTS.md` has the writer work strictly from the specification deltas, and the delta does not imply 2.5's raising sync `invoke` — that guard follows from Decision 2, not from any scenario. Dispatched with the delta alone, the writer will not produce it, and it would then arrive as an implementer's edit to test-writer output, which is the one thing this ordering exists to avoid. Pass Decision 2's *A framework's thread offload* reasoning along too: a writer deriving the loop-free scenario mechanically could write a test that a thread-offloaded sync client also passes.
- [x] 2.2 **Every `propose()` call site is awaited, and every assertion is byte-identical.** All eight files. Per `design.md` Decision 5, an assertion or an assertion message that has to change during this migration is a **finding**, not an edit: this change claims to alter nothing the advisor produces, and a moved assertion is the evidence against that claim. Record it and stop rather than folding it in.
- [x] 2.2a **Prose that names `graph.invoke()` is corrected, and that is not the drift 2.2 forbids.** `test_subcategory_advisor_graph.py` describes its stub as answering "one `AdvisorResult` per `graph.invoke()` call" in its module docstring, its Level section and `_SequencedStructuredChatModel`'s own docstring — a call that raises after section 3. 2.2 pins assertions and assertion messages; it does not pin comments, and leaving prose describing an impossible call is how a file starts lying about its own subject. Update the wording to `ainvoke`; change no assertion while doing it.
- [x] 2.3 The three files carrying no async test yet gain the module-scoped `anyio_backend` fixture returning `"asyncio"`, in the same per-file form the other five already use: `tests/agents/step_handlers/listing/test_subcategory_advisor_graph.py`, `tests/agents/step_handlers/listing/test_subcategory_advisor_finding_and_tools.py`, and `tests/unit/step_handlers/listing/test_subcategory_advisor_schema_conversion.py`. Do **not** add a shared fixture to a `conftest.py` — that is `share-the-unit-test-harness`'s scope, it is last in the queue for the reason that it touches everything, and pre-empting it here would put this change in conflict with it.

- [x] 2.6 **The observable in the new requirement is asserted directly, once.** With a stub whose `ainvoke` yields to the loop before answering and other work scheduled on that loop, the other work is observed to have run by the time the handler returns. - [x] 2.6a **2.6's mechanism is single-yield, not event-synchronised**, and 2.6 is **not** a guard against a revert. `design.md` Decision 2 carries the correction: LangGraph's `ainvoke` yields to the loop *before* running the node, so a companion task progresses whether the node body blocks or not, and 2.6's assertion cannot fail for a blocking call introduced inside `recommend`. Keep it for what it is — the delta scenario's own observable, asserted directly. The stub's `ainvoke` yields once and answers unconditionally; do not synchronise it on an `asyncio.Event` the companion sets, which would make a stub into a scheduler and hang the suite on any change to the node's shape.
- [x] 2.6b **Thread identity guards the node being made synchronous — not every way a node can block.** The stub records the thread its `ainvoke` answered on and the test asserts it is the invoking thread; measured on `langgraph` 1.2.11, a sync node under `ainvoke` answers on a worker thread, an awaited coroutine node on the caller's. ## 3. The source conversion

One edit across three frames. Splitting it leaves the tree in a state where `propose()` calls an entry point the graph no longer answers.

- [x] 3.1 `recommend` inside `build_graph` becomes `async def`, and `structured.invoke([HumanMessage(content=prompt)])` becomes `await structured.ainvoke([HumanMessage(content=prompt)])`. The comment above it — *"No `try` around this: a model or transport fault must surface, not become a recommendation"* — stays and stays true.
- [x] 3.2 `propose` becomes `async def`, and `running.invoke({...})` becomes `await running.ainvoke({...})`. Its docstring gains one line: the graph is async-only after this, and `invoke` on it raises. Nothing else in `propose` moves — all six exits, in order, unchanged.
- [x] 3.3 `advise_sub_category` awaits `propose(...)`. Its own signature does not change; it was already `async def`, which is the whole defect.
- [x] 3.4 `build_graph`'s docstring says the graph it returns is async-only and why — a reader arriving at *"the testable seam"* should learn there that `compiled.invoke(...)` raises `TypeError: No synchronous function provided to "recommend"`, because that error is the structural guard `design.md` Decision 2 relies on and it should not have to be rediscovered from a stack trace.
- [x] 3.5 Do **not** touch the deferred `langgraph`/`langchain_openai` imports, `build_production_graph`, or `_graph()`'s `lru_cache`. `design.md`'s Non-Goals and Decision 6 record why each stays; the module docstring already argues the first at length.
- [x] 3.6 Do **not** add an `asyncio.to_thread` anywhere in this handler. It is rejected here by `design.md` Decision 3 and permitted by the requirement only for a dependency with no asynchronous entry point, which this one has.

## 6. Findings, and what does not get folded in

- [x] 6.1 Record in `docs/deferred-work.md`: `omni_agent/application/graph.py`'s `call_model` node is sync and calls `model.invoke`, the shape the advisor was copied from. Its caller already awaits `graph.ainvoke`, so LangGraph runs it on a thread-pool thread and the loop is not pinned — a genuine difference from the advisor, and the reason this is a finding and not a second defect. The new requirement does not reach it: `omni_agent` is not a step handler. Do not fix it here.
- [x] 6.1a Amend `docs/deferred-work.md`'s existing *The sub-category advisor's supported path has never run* entry. It lists what is untested against a real model in terms of the verdict path alone — the verdict parsing as supported, the veto not firing, `Satisfied` proposed with a pending result delivered. After this change the **async transport** is a second never-run path, and the first classifiable product exercises both at once. Whoever closes that entry needs a reason to look for a stalled loop as well as a wrong verdict; without this line they have none. Its existing trigger to close needs no change, only its list.
- [x] 6.1b Record in `docs/deferred-work.md` the shape no guard catches: a blocking call added inside an otherwise-correct async `recommend`. Established by mutation, not by argument — carry `design.md` Decision 2's table, including that the mutated suite ran in 4.0s against 0.9s while nothing asserted on it, because a wall-clock assertion is what this tier may not hold. State the boundary as a limit of deterministic testing rather than as an oversight, and give a trigger to close (a mechanism that makes loop-blocking observable without timing — `asyncio` debug mode's slow-callback logging is the candidate, and it would serve every handler rather than this one).
- [x] 6.1c Do not let a guard advertise itself as active while being inert. The schema-capture helpers in `test_subcategory_advisor_schema_conversion.py` and the three `wire_*` files wrap `propose()` in `except Exception` and re-raise only `if not model.schemas` — but `with_structured_output(...)` records the schema *before* the model is called, so `schemas` is always populated by the time a fake raises, and every guard was swallowed at that one seam. Let `AssertionError` through unconditionally: it can only have come from the file's own fakes. Verified by mutation both ways — the unit-tier file reported `6 passed` under a reverted `recommend` before the fix and `5 failed, 1 passed` after.

Stop and record it before continuing, rather than folding an unexplained failure into a correction — an unexplained test failure absorbed into a category nobody checked is the defect `restore-the-skipped-unit-tests` was written to clean up.
