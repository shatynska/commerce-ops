## 4. Guard against a repeat

- [ ] 4.1 Add a **new `tests/conftest.py`** holding a `pytest_sessionfinish` hook that fails the session when any test under `tests/unit` or `tests/agents` was skipped, naming each one and its reason. Not `tests/unit/conftest.py`: a conftest is loaded only for the paths collected, so a hook there is never registered by `uv run pytest tests/agents` and that tier runs unguarded and silently. See `design.md` Decision 3.
- [ ] 4.2 It must read **`TestReport`s, not collection**. The skips this guards against are raised by an autouse fixture during setup, so `pytest_collection_modifyitems` never sees them and a guard written there passes vacuously — which is a guard that is worse than none, because it reads as protection.
- [ ] 4.2a Four mechanics, each of which otherwise costs a debugging session at 4.5:
  - **Accumulate reports in `pytest_runtest_logreport`, in this same conftest.** Reading the terminal reporter's `stats` is the tempting shortcut and it returns `None` when the terminal plugin is disabled — it fails *open*, which is the one failure mode a guard must not have.
  - **Fail by setting `session.exitstatus`, not by raising.** An exception raised inside `pytest_sessionfinish` surfaces as `INTERNALERROR`, not as the clean failing session naming each skipped test that 4.5 asserts.
  - **`pytest_sessionfinish`, never `pytest_sessionstart`** — the latter fires before non-initial conftests load. Recorded so a later tidy-up does not move the work and silently disarm the guard.
  - **No work at import time.** `tests/unit/test_integration_tier_database_resolution.py` `exec_module`s a conftest inside the commit-time tier; `isolate-tests-from-the-shared-runner` task 3.3 records this hazard for the same reason.
- [ ] 4.3 Scope it by path to `tests/unit` and `tests/agents`. `tests/integration` skips legitimately and by specification when no database resolves (`AGENTS.md`), and failing those would break a tier this change does not touch. The **path filter**, not the conftest's location, is what excludes the integration tier.
- [ ] 4.4 **Do not treat `xfail` as a skip.** `TestReport.skipped` is true for an `xfail`ed test as well as a skipped one, so a hook that does not distinguish them bans a marker nobody proposed banning. No `xfail` exists under `tests/` today; three file docstrings record "2 xfailed" from 2026-08-28, so it is a shape this repository has used.
- [ ] 4.5 Verify the **true positive, in both tiers**: temporarily add a plain `pytest.skip` inside one test body under `tests/unit` and another under `tests/agents`, confirm the session fails naming each, then revert. Run the `tests/agents` case as `uv run pytest tests/agents` alone — that invocation is the one 4.1's placement exists to cover, and running it only as part of the pair cannot show the difference.
- [ ] 4.6 Verify the **two skips that already exist** in this tier behave as `design.md` Decision 3 predicts: `test_admin_assets_route.py:339` (skips when `git` is absent from `PATH`) and `test_the_advance_trigger_is_the_webhooks_alone.py:159`. Neither fires on a normal machine, which is why "0 skipped" was first mistaken for "no skips exist". Force the git case — run the tier with `git` removed from `PATH` — and record what the guard does. If it fires, add a narrow allowance for that **named test**, never a filename pattern; a filename pattern is the mechanism this whole change removes.
- [ ] 4.7 Verify the **false positive is absent**: run `tests/integration` and confirm the guard does not fire on its database skips. On a machine where a database *does* resolve, that tier skips nothing and the check is vacuous — say so in the record rather than reporting a green run as evidence, and force the case by running it with no resolvable `DATABASE_URL`.
